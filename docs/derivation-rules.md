# Derivation rules

Every word and number on the wall is computed from Jobber and the two sheets by one pure function in `packages/domain/src/derive/`. Each rule takes `now` as a parameter and has a table test in `packages/domain/test/`. This page is the plain-English version. If the code and this page disagree, the code is wrong until the owner says otherwise.

| Rule | Module | What it does | Decisions |
|---|---|---|---|
| Title parse | `title.ts` | Splits `CITY - TOKEN TYPE - LAST`. Token STD/STANDARD/HVAC/SERVICE/WARRANTY → Standard; CONSUMERS/CEHN/CE INS → CE insulation; CONSUMERS HVAC/CE HVAC → CE HVAC; no token → `PROGRAM` (fail-closed: treated as program work). Scope from the type words and the visit instructions: ATT, WALL, AIR, BD, HVAC, EVAL, SVC, or `—`. Label is always `LASTNAME · CITY · SCOPE`; cities longer than 10 characters are cut to 9 plus a dot. | 3, 4 |
| Needs attention | `attention.ts` | One line per job in Jobber's Late, Action required or Requires invoicing bucket. Age counts from the first poll that saw the job in that bucket; before the service has seen it, from Jobber's `updatedAt`, shown with `~`. Order: Late, Action required, Requires invoicing; oldest first. The line vanishes when the bucket does. | 29 |
| Note grammar | `notes.ts` | Reads only four line shapes in a Jobber note: `CLOSE: <code>( / <reason>)`, `VISIT RESULT: <value>( / <reason>)( — free text)`, `PR: day n of m`, `ACK H:MM II`. Newest line of each kind wins. Anything else is ignored; garbage never breaks the board. | 11, 41, 42 |
| Visit result | `visitResult.ts` | Job-form answer, else the newest house-format note (close codes C/CM → Completed, PR → Prepped on a planned prep day else Return needed, NW-R/NW-W → Not started, RS → Customer cancelled), else a queued crew recap, else `unknown`. Never a default. `Problem` only ever comes from the form, a `VISIT RESULT: Problem` line or a recap. | 10, 11, 21, 46 |
| Prep day | `visitResult.ts` | A visit was planned as a prep day when a later visit on the job already existed when it started, or its instructions say `PR: day n of m` with n < m, or the word `prep`. | 46 |
| Answered | `answered.ts` | Answered when a result exists from any source, or Jobber's unanswered-form count is 0 on a visit that did have a form. Unanswered when the count is above 0. Unknown when no form was ever seen (a 0 count on a form-less visit proves nothing). Counted only after the visit is complete or 30 minutes past its scheduled end. | 10, 18, 21 |
| Card chip | `cards.ts` | Before start: `○ NOT STARTED` (grey). From start until 30 minutes after the scheduled end: `● NOW`. After that, still open in Jobber: `⚠ LATE` (red). Complete with no answer: `◌ NO RESULT` (amber). With a result: the result word and icon. A Completed visit on a Requires invoicing job shows the review state instead: `◔ AWAITING REVIEW` → `✎ FIX` / `❚❚ HOLD` → `✓✓ READY` → `✓✓ DONE` (grey) once invoiced. Cards leave the lane at Detroit midnight. There is no "crew arrived" signal in v1, so the card never claims a visit has not started once its start time has passed. | 27, 34, 48 |
| Problem ACK | `cards.ts` | A `Problem` with no `ACK` line for 15 minutes gets the red border; the ACK is a note line, the clock starts at the result. Visual only. | 41 |
| Review-row match | `reviewMatch.ts` | Exact on the sheet's `Jobber job id` or `Job #`. Otherwise inferred when the file stem's last name matches exactly one job that has a completed visit within 3 days of the install date. Two candidates or none → unmatched: shown in REVIEW's unmatched panel, never as a verdict on the wall. | 5, 7, 8 |
| Cannot-invoice reason | `cannotInvoice.ts` | First rule that fires: PROGRAM-WAIT (submitted, not yet accepted or returned) → HOLD (hold reason not about an inspection or permit) → INSPECTION/PERMIT → FIX OPEN (latest FIX not Fixed/Accepted/Submitted and no later READY) → RETURN NEEDED (last result Return needed or Problem, no future visit) → BLOWER DOOR FAIL (`pre > post` parses and the reduction is under 20 %) → FORM/QUANTITIES MISSING → AWAITING 2ND REVIEW → READY TO INVOICE → AWAITING 1ST REVIEW (default). | 30, 43 |
| Stage clocks and colour | `cannotInvoice.ts` | Clocks: completed → 1st review → 2nd review → submitted → accepted. Days count in the stage SealTech owns right now. Amber at 3 days, red at 7. Hard red at 20 days since completion with no submission. PROGRAM-WAIT is grey (the program's clock, not ours). | 31 |
| Line owner | `owner.ts` | FIX → `CREW`, HOLD → `OFFICE` (role words, never a name). Otherwise a huddle override wins; else return/blower-door/forms → the crew lead's initials from the latest visit; reviews, inspection, program wait, ready → the office person's initials. | 16, 33 |
| Leak guard | `leak.ts` | A completed job with no future visits and uninvoiced work that Jobber did not put in Requires invoicing (the "no reminders" setting hides it) gets a `NO-REMINDER` tag on the rail. A zero-total job gets `NO CHARGE?`. Tags only: the hero number stays Jobber's own count. | 32 |
| Plan kept | `planKept.ts` | Yesterday's visits with a result, minus Customer cancelled, are "planned". Kept = Completed, or Prepped on a planned prep day. Everything else is a miss under its reason. Visits with no result are shown as "(n unknown)". | 44, 46 |
| First-pass READY | `firstPass.ts` | Per job, the earliest first-pass verdict in the Monday-to-Sunday week; READY count over total. Company-level on the wall; per crew only on the manager scorecard. A dash when nothing was reviewed. | 35, 44 |
| Staleness | `staleness.ts` | A source is green under 10 minutes since its last complete successful load, amber to 30, red after. The board is stale when Jobber is red: the banner replaces the focus line and the numbers stay (they are the last good ones). | — |
| Dedupe | `dedupe.ts` | Every write has a submission id (hash of kind, target, pass, payload). A second identical review tap within 2 minutes is dropped. A recap replaces a queued one and is refused once the first is in Jobber. | 12 |
| Snapshot | `snapshot.ts` | Composes everything above, validates against the schema, and rejects any text that looks like money, a street address or a phone number. The Review sheet file name is cut to program, scope and last name. Invoiced jobs leave the cannot-invoice list even if Jobber still shows the bucket. | 4 |

## What the board does not derive

- Nothing from `actionsUponComplete` (same on every visit).
- Nothing from `visitsInfo.pastCount` (observed wrong).
- No stage word that is not Jobber's own bucket.
- No name next to any quality number on the TV.
